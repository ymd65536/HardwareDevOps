# Manufacturing as Code PoC：GitHub Copilot ディスプレイスタンド

## 概要

本リポジトリは、GitHubとOpenSCADを活用した製造ワークフローの最初のPoC（概念実証）です。その目的は、3Dプリントされる部品をソフトウェアの成果物として扱うことにあります。具体的には、ソースコードをGitでバージョン管理し、自動化によって再生成を行い、STL形式への書き出しやPNG形式のプレビュー生成を通じて検証を行います。

このPoCでは、GitHub Copilotのフィギュアを飾るための、最小限の構成かつパラメータ制御可能なスタンドを対象としています。公式のGitHub Copilot 3Dモデル自体には意図的に手を加えず、フィギュアをディスプレイするためのスタンドを別途作成するアプローチをとっています。

## 設計思想

- 形状をOpenSCADのソースコードとして記述する。
- 主要な寸法にはマジックナンバーではなく、名前付き変数を使用する。
- OpenSCADのモジュール機能を活用し、設計をモジュール化する。
- 将来的な締結部品やアクセサリーの追加を見据え、拡張用の領域を確保しておく。
- 視覚的な複雑さよりも再現性を優先する。

## モデルの意図

このスタンドはコンパクトなベース形状をしており、以下の要素を備えています。

- 安定性を確保するための広い接地面積
- フィギュアを保持する小型の上部台座
- 接地面となるトッププレート
- ラベル表示用のネームプレート配置エリア
- 将来的なねじ穴やアクセサリ取り付けのための専用マウンティング機能
- 穴あけやモジュール式インサートの取り付けを想定した将来的な拡張エリア

主要なパラメータはOpenSCADのソースコード内で定義されており、スタンドの幅、奥行き、高さ、プレートの厚みなどの変数を調整することで変更可能です。`mounting_feature()` モジュールにより、ハードウェア拡張を本体の主要形状から分離し、後から調整しやすい構造になっています。

## ローカルでの生成手順

OpenSCADがまだインストールされていない場合は、まずインストールしてください。

### 新規チェックアウト後のクイック実行

```bash
chmod +x scripts/build-model.sh
./scripts/build-model.sh
```

### 手動での実行手順

STLのレンダリング:

```bash
openscad -o artifacts/copilot-stand.stl src/copilot-stand.scad
```

PNGプレビューのレンダリング:

```bash
openscad -o artifacts/copilot-stand.png --imgsize=1600,1200 src/copilot-stand.scad
```

ファイル出力を行わないプレビューモード（任意）:

```bash
openscad src/copilot-stand.scad
```

設計の妥当性確認（任意）:

```bash
python3 scripts/validate-stand.py
```

別のサイズプロファイルを使う場合（任意）:

```bash
STAND_WIDTH=100 STAND_DEPTH=80 STAND_HEIGHT=52 ./scripts/build-model.sh
```

この方法により、SCADソースを直接編集せずに、別サイズのスタンドを簡単に再生成できます。

## GitHub Actionsの役割

`.github/workflows/build-model.yml` に記述されたワークフローは、以下の処理を行います。

1. リポジトリをチェックアウトする
2. 軽量な設計チェックを行うためのPython環境をセットアップする
3. ランナーにOpenSCADをインストールする
4. `scripts/validate-stand.py` を使用してパラメータセットを検証する
5. SCADソースからSTLを生成（レンダリング）する
6. PNGプレビュー画像を生成する
7. 生成された両方の成果物（アーティファクト）をGitHub Actionsのアーティファクトストアにアップロードする
8. 生成または検証のいずれかのステップで失敗した場合、エラー終了する

これにより、ハードウェア開発におけるDevOpsの基本サイクルが構築されます。

```text
設計変更
→ Gitコミット
→ CIビルド
→ STL生成
→ PNGプレビュー
→ 成果物の保存
```

## 現在の検証状況

このPoC（概念実証）は、当該モデルが構文的にレンダリング可能であり、自動生成できることを検証するものです。この設計が、あらゆるプリンター、素材、またはフィギュアの形状に対して完全に最適化されていることや、物理的に検証済みであることを保証するものではありません。

## 現在未解決の事項

現時点では、設計ドキュメントにおいて以下の未確定事項が明示的に記録されています。

- フィギュアの正確な設置面積（フットプリント）および質量の許容範囲
- プリンター固有の肉厚要件
- インフィル（内部充填）および造形方向（オリエンテーション）に関する前提条件
- 将来的な固定部品やアクセサリーモジュールの取り付けに必要な許容公差

これらの項目は、不確かな推測に基づくのではなく、意図的に「将来の改善候補」として残されています。

## 「Manufacturing as Code（コードによる製造）」の今後の展開

次に実施すべき有益なステップは以下の通りです。

- 寸法および形状に関する自動妥当性確認（サニティチェック）の追加
- スライサーやプリンター固有の製造プロファイルの追加
- 公差およびクリアランスの検証機能の追加
- リリース成果物の概要やBOM（部品表）のようなメタデータの追加
- プルリクエストにおけるプレビュー差分表示および目視確認機能の追加

## このリポジトリの使い方

1. リポジトリをクローンし、ローカルのシェルで開く
2. OpenSCAD がインストールされていることを確認する
3. ビルドスクリプトを実行する

```bash
./scripts/build-model.sh
```

4. `artifacts/` 配下に生成された成果物を確認する
   - `copilot-stand.stl`
   - `copilot-stand.png`
5. 事前に環境変数を設定して、別サイズのプロファイルを生成することもできる

```bash
STAND_WIDTH=100 STAND_DEPTH=80 STAND_HEIGHT=52 ./scripts/build-model.sh
```

6. ソースを変更してコミットし、GitHub Actions に push すると、自動的にモデル生成と成果物保存が実行される

このリポジトリは小さくても、ハードウェアPoCにおける設計、検証、生成、成果物保存の基本サイクルを示すための最小構成として意図されています。
